## 리뷰가 확인한 6개 리스크

1. **중복 계산** — `Counter` → `v > 1` 필터 → `sum(v-1)` = **초과분** 의미. 3회 등장이 2건
   기여. off-by-one·이중계상 없음
2. **비문자열 항목** — `isinstance(x, str)` 로 배제. `123`·`null` 이 계상에 들어가지 않음
3. **`isinstance(fm, dict)` 가드** — YAML 파싱 후 `fm.get()` 전에 위치. 리스트/스칼라
   frontmatter 페이지를 건너뛰는 것이 안전하며, `total`·`ok`·P계층·`missing_file` 에 기여할
   페이지를 건너뛰지 않음. **기존 코드가 이런 페이지에서 crash 했으므로 hardening 이기도 함**
4. **기존 계상 불변** — 중복 검사는 새 키만 증가시키고 `src`·`names`·기존 루프 상태를
   건드리지 않음. `total`/`ok`/`p1`/`p2`/`p3`/`missing_file` 영향 없음.
   → `test_duplicate_scan_does_not_break_other_counts` 가 이를 직접 단언
5. **dead code** → 위 [low]
6. **테스트 비-vacuous 확인** — `test_full_scan_aggregates_across_pages` 가 서로 다른
   카테고리(`entities/`·`concepts/`) 2페이지를 excess 1·2 로 만들어 `duplicate_pages == 2`,
   `duplicate_refs == 3` 을 직접 검증. "전수 스캔" 주장을 실제로 증명함
