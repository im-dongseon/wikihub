실측 결과:

```

  Environment=WIKIHUB_YAML=/tmp/wg-render/wh/wikihub.yaml   ← 주입됨
  Environment=WIKIHUB_HOME=...                                ← 없음

따라서 실제 경로 = 2순위 (WIKIHUB_YAML 부모)
실행 검증: /tmp/wg-sysd/.wl.lock  → yaml 부모 기준 ✅
```

**fallback(3순위)은 systemd 경로에서 도달하지 않습니다.** 인스턴스별 분리 디렉토리라
공유되지 않습니다. 3순위는 두 env 가 모두 없는 ad-hoc 호출 전용이며, 단일 운영자
환경에서 무해합니다.

→ 코드 주석으로 근거를 명시했습니다(설계 의도 기록). 로직 변경 없음.

### [low2] 테스트 realism — systemd 는 wrapper 를 직접 exec

테스트가 `bash "$GUARD"` 로 실행하지만 systemd 는 wrapper 를 **직접 exec** 합니다.
이 차이를 제거하고, 직접 실행이 성립하는 조건(shebang + 실행 권한)도 검증에 추가했습니다.

```
추가 검증: wrapper 실행 권한 · shebang (#!/usr/bin/env bash)
변경: bash "$GUARD" sleep 8  →  "$GUARD" sleep 8
결과: PASS 15 → 16
```

## 리뷰가 확인한 핵심 성질 (7항목 전부 "No findings")

1. **lock 세션 수명 유지** — `exec 200>lock` → `flock -n 200`(no `-o`) → `exec "$@"` 3단이 정확
