## 리뷰가 확인한 항목 (PASS 근거)

**(a) chmod 안전성** — `sync.py:295-300` 에서 `os.replace` **이후** 실행되므로 최종 경로가 대상입니다. chmod 실패는 내부 핸들러가 잡아 로그 후 삼키며(`lint.md` 의 warn-only 정책과 일치), 외부 `except` 의 tmp unlink 는 replace 후 이미 사라진 경로라 중첩 `except OSError: pass` 가 흡수하고 원 예외를 re-raise 합니다. **데이터 손실 없음, tmp cleanup 무손상.** 유일한 caller 는 `_handle_create_or_modify`.

**(b) false negative 위험 = LOW (fails-safe)** — 파싱 실패 시 **원본 문자열을 반환**해 기존 `!=` 동작으로 퇴화합니다. 즉 최악의 경우 spurious `modified`(과검출)이지 missed change(과소검출)가 아닙니다. `None`/빈/naive/garbage 전부 통과. canonical form 은 round-trip 합니다.

**(c)** 신규 helper 의 legacy caller 없음. `compute_diff` signature·`DiffEntry.mtime` payload 무변경. 저장된 `file_map` 값 무변경.

**(d)** 두 비교 지점 모두 동일하게 변환 (`mount_diff.py:169` id 기반 / `:260` path 기반).

**(e)** 신규 Step 0 결론 표(`lint.md:73-84`)가 headless "never clarify"(`lint.md:515`)와 Step 8.1 no-stall(`:440`)을 **강화**하며 모순 없음.

**(f) 테스트가 revert 시 실패함을 확인** — `test_sync.py` umask 0o077→0600 / overwrite, `test_mount_diff.py` ImportError(helper 부재) + offset⇒diff 0. over-normalization guard 1건 포함.
